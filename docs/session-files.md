# 현재 실험의 입력 파일

목적은 한 실험에서 비교하던 입력과 기준을 다른 창·기기에서 다시 여는 것이다. 프로젝트 관리, 설계 계산서, 과거 결과의 보증 보관을 추가하지 않는다. 앱 이름은 개인용 **흙의 감각**이다.

## 파일의 의미

- 파일명은 `soil-sense-<실험 key>.json`이다.
- 형식 식별자 `soil-sense-experiment`, 현재 저장 버전 `5`, `experiment` 객체만 허용한다. 기존 배포판의 버전 `1`·`2`·`3`·`4` 파일도 아래 명시한 이전 규칙으로 읽는다.
- 실험 객체는 `module`, `question`, `current`, `baseline`, `compare`만 가진다. 다른 실험, 검색어, 전체 방문기록, 사용자 이름, 임의 HTML, 계산 결과를 담지 않는다.
- 숫자는 앱의 내부 계산 단위로 저장한다. 예를 들어 얕은기초 E의 25 MPa는 JSON에서 `25000` kPa다. 미리보기에 저장 단위를 함께 표시한다.
- 값을 복원하면 선택한 계산 모형으로 다시 계산한다. 기존 흙막이 입력은 기존 선형 앵커 모형으로 읽고, `modelVersion:2`인 새 입력만 단계별 흙막이 모형을 사용한다. 새 기본값과 병합하여 이전 예제의 모형을 바꾸지 않는다. 계산 결과 자체를 저장하는 스냅샷 형식은 아니다.
- 버전 1의 토압·층별침하·축방향 말뚝 파일은 당시 공개한 질문과 필드 구성을 `SessionSchemaV1`으로 대조한다. 사면의 버전 1·2 파일은 `SessionSchemaV2`의 같은 기존 필드·질문 목록으로 대조한다. 원래 입력·기준·질문은 그대로 두고 새 질문 전용 필드만 기본값으로 준비하며, 미리보기에 이를 알린다. 원래 필드의 누락·미등록 필드·이전 버전에 없던 질문은 거절한다. 흙의 분류 버전 1·2·3 파일은 `SessionSchemaV3`로 기존 10개 필드를 대조하고 침강 전용 4개 입력만 기본값으로 준비한다. 버전 4의 완전한 흙의 분류 입력과 변경 없는 실험에는 누락 필드를 보충하지 않는다.
- 흙막이 버전 1~4는 기존 11개 입력과 `displacement`/`moment` 질문만 허용한다. 버전 5는 그 기존 모형 또는 `modelVersion:2`의 명시적인 중첩 입력을 허용한다. `ExcavationSchema`가 지반·되메움·수위·지보재·평면·관찰 상태의 필수/선택 필드와 자료형을 검사하며, 미등록 필드를 허용하지 않는다. 기존 선형 예제도 버전 5로 다시 저장할 수 있지만 새 모형 입력을 끼워 넣지 않는다.

## 사용자 흐름과 덮어쓰기

`입력 저장`은 현재 실험 하나를 저장한다. `파일 열기` 후 실험 이름·질문·비교 표시 여부·파일의 현재값과 기준값을 확인한다. 실험·필드 이름은 앱 안의 목록에서 가져오고 파일의 문자열로 제목을 만들지 않는다. 체별 자료와 흙막이 중첩 입력은 항목 수를 표시하고 접은 상세에서 전체 내용을 확인할 수 있다.

미리보기까지는 앱 입력을 수정하지 않는다. `이 실험에 적용`을 눌러야 해당 실험의 현재값·기준·질문·비교 표시를 함께 적용한다. 취소와 Escape는 무변경이다. 다른 실험 입력은 유지한다. 적용 직전 대상 실험의 전체 상태를 하나의 되돌리기 항목으로 저장하며, 기존의 일반 입력 되돌리기 및 브라우저 자동저장도 유지한다. 실제 상태 저장과 되돌리기는 공통 앱의 hook이 담당한다.

현재 질문의 입력은 계산 가능한 상태여야 파일로 저장·복원할 수 있다. 다른 질문에서 사용하던 비활성 숫자가 비어 있거나 물리 범위를 벗어난 경우에는 현재 질문을 막지 않고 보존한다. 다만 자료형, 유한수, enum, 고정 모형 상수 검증은 비활성 항목에도 항상 적용한다. 비교가 켜져 있으면 기준도 같은 질문에서 계산 가능해야 한다. 비교가 꺼져 있고 기준을 현재 질문에서 계산할 수 없는 경우 미리보기에 이유를 표시하며, 기준값과 비교 끔 상태를 그대로 보존한다.

## 구현 계약

`src/learning-session-files.js`는 함수만 선언한다. 불러오는 것만으로 DOM·localStorage·현재 상태에 접근하지 않는다.

```js
const service = createLearningSessionFiles({
  catalog: makeLearningSessionCatalog({ modules, defaults, labs: labRegistry }),
  validate: (module, data, question) => compute(module, data, question)
});
installLearningSessionFiles({
  service,
  host: document.querySelector('.control-panel'),
  getSnapshot: () => ({
    module: state.active,
    question: state.question[state.active],
    current: state.data[state.active],
    baseline: state.baselines[state.active],
    compare: state.compare[state.active]
  }),
  beforeExport: finishPending,
  applySnapshot(snapshot) {
    // 동기 hook: 편집 마무리 → 대상 실험의 원자 undo 저장 →
    // module/question/current/baseline/compare 적용 → render/save.
  }
});
```

순수 API는 `serialize(snapshot) → {text, filename, snapshot, preview, warnings}`, `parse(text) → {snapshot, preview, warnings}`, `inspect(snapshot)`를 제공한다. 반환 상태는 별도 복사본이다. `validate`는 전역 질문을 임시 변경하지 않고 넘겨받은 질문으로 계산해야 한다. `{valid:true}`만 통과한다. 모델 예외는 일반 검증 실패로 변환한다.

공통 앱에서 추가할 hook의 계약:

1. `compute(key, data, questionOverride)`에서 입력 범위·activeFields·핵심 모형 모두 같은 override 질문을 사용한다.
2. 파일 적용 시 data만이 아니라 question/baseline/compare/baselineName도 한 undo 항목에 보관한다. 다른 실험의 history는 변경하지 않는다.
3. 적용 후 해당 실험으로 이동하고 화면과 저장소를 갱신한다. 기본 지지력 첫 방문의 자동 비교 켜기 등이 가져온 `compare:false`를 다시 뒤집지 않아야 한다.
4. `applySnapshot`은 동기식이며 실패 시 예외를 던진다. 비동기 원격 저장·파일 업로드는 없다.

## 검증 및 방어

- UTF-8 256 KiB 상한을 파일 크기와 문자열 길이 양쪽에서 확인한다. 실험의 체별 배열은 최대 512행이며 흙막이 지보재 목록은 최대 24개다.
- JSON 이외의 형식, 잘못된 버전, 미등록 실험/질문, 누락/미등록 key, 잘못된 불린·숫자 문자열·미등록 enum을 거절한다.
- NaN/Infinity는 serialize 이전에 확인해 JSON의 조용한 `null` 치환을 막는다. JSON의 `1e999`도 거절한다.
- `__proto__`, `constructor`, `prototype` 속성 및 지나치게 깊은 객체를 거절한다. 문자열을 eval하지 않는다.
- 고정 물 단위중량, 기본 얕은기초의 Df=0·ν=0.30, 횡방향 말뚝 요소 수 등의 내부 상수는 파일에서 바꿀 수 없다.
- 배열 행의 key와 숫자 형식을 확인한다. 실제 물리 조건은 해당 질문의 기존 계산기로 다시 검증한다.
- 가져온 값은 `createElement`와 `textContent`로만 표시한다. 파일 내용을 `innerHTML`에 삽입하지 않는다.
- 읽기 요청을 순번으로 구별하여 취소하거나 더 새 파일을 선택한 뒤 이전 읽기가 미리보기를 덮지 않게 한다.
- 저장·읽기·취소·실패는 앱 상태를 직접 변경하지 않는다. 명시적 적용 callback만 변경을 허용한다.

`tests/session-files.test.mjs`: 순수 검증 34개 통과. 이전 제공판의 실제 구조로 보존한 JSON 파일들에서 버전 1의 기존 세 실험과 버전 1·2 사면의 이전 및 누락/위조 거절을 확인한다. 현재 등록된 모든 실험/질문의 기본 상태 왕복도 한 검사 안에서 대조한다. 이는 외부 전문가나 실제 학습자의 검증이 아니라 개발자 구현 검증이다.

2026-09-29 호환성 추가: `tests/excavation-session.test.mjs`에서 이전 흙막이 v1~4의 정확한 입력·기준·단계·선형 결과 보존, 기본값 비병합, v5 중첩 입력 왕복, 이전 버전으로 위장한 새 입력 거절, 중첩 스키마 및 초안 보존을 확인했다. `tests/workspace-adapter.test.mjs`에는 이전 흙막이·라이브러리 원문·복습 진행·별도 계산서의 함께 복원을 추가했다. 전체 작업공간 봉투와 세 저장 키는 그대로이며 이 작업은 실제 사용자 자료를 읽거나 옮기지 않는다. 새 흙막이 화면의 브라우저 검증은 이 순수 저장 테스트와 별도로 수행한다.

화면 변경 시에는 미리보기·취소·Escape·적용·되돌리기·재방문·잘못된 파일의 무변경, 좁은 화면의 버튼/열 표시를 별도로 확인한다. 이 공개 배포본에는 과거 브라우저 검사의 스크립트와 실행 산출물을 포함하지 않는다.

추가로 단일 HTML을 `file://`에서 열어 오프라인 JSON 다운로드와 변경 후 명시적 복원을 각각 확인했다. 네트워크·서버 연결이 필요하지 않았다.

## 6단계 개발자 복습 흐름 추가 점검

1440 px / 390 px에서 기존 검사와 겹치지 않는 다음 연속 과제 18개 조건을 점검했다: ‘부주면마찰’ 검색으로 해당 질문 열기 → 두 입력 변경 → 기준 저장 → 상대변위 해설과 변경 내역 확인 → 페이지 다시 열기 → 잘못된 하중 입력 → 잘못된 기준 저장 방지 → 되돌리기, 그리고 ‘배수거리’ 검색 → 층두께와 배수조건 비교 → 재방문.

질문·현재값·기준값·모드가 유지됐고, 오류에서 유효한 그림으로 복구했으며 가로 넘침과 JavaScript 예외가 없었다. 이 개발자 과제에서 새 중대 동작 오류는 발견하지 않았다. 모바일 검색 Enter 이후 activeElement가 검색창으로 남는 관찰을 추가 확인했으나, 실제 다음 Tab은 열린 실험의 질문 버튼으로 정상 이동하여 접근 장애로 기록하지 않았다. 실제 사용자의 첫 조작 시간, 이해도, 복습 효과는 측정하지 않았다.
